# Regrouping demo pack

Small synthetic datasets and runnable requests for Ticket #58 (identifier warnings and
category regrouping). Everything here is generated by `python scripts/build_demo_pack.py`,
which calculates the expected values directly with pandas and scipy.
`test/test_demo_pack.py` runs every case through the API and compares it with `cases.json`
using the stated tolerances.

## Run a case by hand

```bash
python scripts/dev_seed.py            # creates dev1@example.com / devpassword1
curl -c jar.txt -H 'Content-Type: application/json' -d '{"email":"dev1@example.com","password":"devpassword1"}' http://127.0.0.1:8000/api/auth/login
curl -b jar.txt -F file=@datasets/sparse_categories.csv http://127.0.0.1:8000/api/analyze   # note analysis_id
curl -b jar.txt -H 'Content-Type: application/json' -d '<request body below>' http://127.0.0.1:8000/api/reports/$ID/comparisons
curl -b jar.txt http://127.0.0.1:8000/api/reports/$ID/comparisons              # reopen the saved results
curl -b jar.txt -X POST http://127.0.0.1:8000/api/reports/$ID/suggestions      # explanations (Ticket #47)
```

Run from `docs/examples/demo-pack`. Numeric tolerances are a relative 1e-6; counts must match exactly.

## identifier_warning (Ticket #58)

**Identifier-like grouping column.** Is customer_id a meaningful grouping for spend?

* Dataset: `datasets/identifier_like.csv`
* Request body:

  ```json
  {"comparison_type": "categorical_numeric", "group_column": "customer_id", "value_column": "spend"}
  ```

* Expected HTTP status: 201
* Expected values: see `cases.json` (`expect`).
* Warning contains: "may be an identifier"
* Supports: Warning beside the result with the reasons; no chart should be trusted until the user confirms.
* Notes: 40 of 40 values are distinct. The existing category limit is unchanged.

## valid_combination (Ticket #58)

**Valid user-defined combination.** Is income distributed differently for HS versus a combined Degree group (BA, MA, PhD)?

* Dataset: `datasets/sparse_categories.csv`
* Request body:

  ```json
  {"comparison_type": "categorical_categorical", "group_column": "education", "outcome_column": "income", "category_mappings": {"education": [{"label": "Degree", "categories": ["BA", "MA", "PhD"]}]}}
  ```

* Expected HTTP status: 201
* Expected values: see `cases.json` (`expect`).
* No warning containing: "expected counts below 5"
* Supports: Before/after category-count bar chart.
* Notes: Four groups become two. The mapping, original counts and regrouped counts are returned. A different p-value is not evidence the regrouping is better.

## method_changes (Ticket #58)

**Combination that changes the number of groups and the method.** Does age differ by education when everyone above high school is combined?

* Dataset: `datasets/sparse_categories.csv`
* Request body:

  ```json
  {"comparison_type": "categorical_numeric", "group_column": "education", "value_column": "age", "category_mappings": {"education": [{"label": "Degree", "categories": ["BA", "MA", "PhD"]}]}}
  ```

* Expected HTTP status: 201
* Expected values: see `cases.json` (`expect`).
* Supports: Before/after counts plus a notice that the method changed from a rank to a mean comparison.
* Notes: Four groups use Kruskal-Wallis; two groups use Welch's t-test.

## regroup_both_columns (Ticket #58)

**Regroup the group and the outcome column.** Mappings can be given for both categorical columns of a categorical comparison.

* Dataset: `datasets/sparse_categories.csv`
* Request body:

  ```json
  {"comparison_type": "categorical_categorical", "group_column": "education", "outcome_column": "income", "category_mappings": {"education": [{"label": "Degree", "categories": ["BA", "MA", "PhD"]}], "income": [{"label": "below", "categories": ["low"]}]}}
  ```

* Expected HTTP status: 201
* Expected values: see `cases.json` (`expect`).
* Supports: Before/after charts for both columns.
* Notes: Renaming a single category is allowed. Unmapped categories keep their labels.
